# Project Radar v3 rename and transfer policy

Repository paths can change when projects are renamed or transferred. V3 preserves path-based compatibility while also using GitHub’s stable numeric repository ID and node ID when available.

A confirmed rename or transfer can connect prior and current repository paths through a versioned identity edge. Historical observations remain associated with the stable repository identity and retain the path observed at that time. A path disappearing from bounded discovery is not automatically classified as a rename, transfer, or deletion.

Permanent profile pages should preserve canonical identity, expose prior paths when verified, and avoid assigning an old project’s history to a newly created repository that later occupies the same path.
