# Project Radar v3 adoption evidence policy

Adoption evidence remains ecosystem-specific and is not treated as a universal popularity scale.

PyPI, npm, crates.io, RubyGems, Packagist, NuGet, Maven Central, Docker Hub, GitHub releases, and future registries use different counting rules, retention windows, mirrors, bots, dependency behavior, and definitions of a download. Raw values retain their provider, unit, time window, observation time, freshness, stable package identifier, confidence, and coverage.

A missing package mapping or unavailable registry response remains missing. The system never assumes that a repository name is its package name and never assigns zero adoption to an unmapped repository. Cross-ecosystem normalization is experimental and shadow-only.

Adoption signals may support discovery and comparative analysis within a compatible source and window. They do not prove active human users, revenue, security, maintainership quality, or commercial success.
