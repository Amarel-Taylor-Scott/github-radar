# Project Radar v3 correction policy

Corrections require verifiable evidence and preserve an audit trail.

Supported corrections include repository renames, transfers, duplicate identities, package mappings, catalog assignments, project classification, broken links, license identifiers, provider-evidence discrepancies, profile factual errors, and benchmark labels. The correction form should cite authoritative repository, registry, provider, or standard documentation and disclose affiliations.

Factual corrections update the next versioned snapshot. Historical snapshots retain what was observed at their generation time unless a separate errata record is required. Corrections do not grant ranking bonuses and do not convert missing evidence into inferred facts.
